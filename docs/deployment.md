# 배포

## 1. Supabase

1. 프로젝트를 만들고 Auth에서 이메일 비밀번호 로그인을 켭니다.
2. `supabase/migrations`의 세 파일을 번호 순서대로 SQL Editor 또는 Supabase CLI로 적용합니다.
3. `20261020000003_storage.sql`은 `storage` 스키마가 있는 Supabase에서만 적용합니다.
4. 첫 사용자는 `/auth`에서 가입한 뒤 “비공개 그룹 만들기”를 실행합니다. 그 사용자가 방장입니다.
5. 방장이 초대를 만들면 코드는 그 응답에만 나타납니다. 다른 사용자는 가입 후 그 코드로 수락합니다. 가입만으로 그룹에 들어가지 않습니다.
6. 활성 멤버가 세 명이 되면 추가 수락은 데이터베이스에서 거절됩니다.

이 저장소를 만든 환경에서는 위 SQL을 실제 프로젝트에 적용하지 않았고, 따라서 RLS와 동시 수락을 라이브로 검증하지 않았습니다.

## 2. 앱

Vercel 또는 Node 서버에 배포합니다. 환경 변수는 `docs/configuration.md`와 같습니다. 서버리스 요청 안에서는 작은 이미지의 픽셀 변환만 처리합니다. 원본은 변환 실패 시에도 유지됩니다.

`sharp`는 서버 외부 패키지로 설정되어 있습니다.

## 3. 확인

배포 후 세 계정으로 다음을 직접 확인해야 운영으로 볼 수 있습니다.

- 초대 만료, 재사용, 네 번째 멤버 거절
- 멤버 A의 비공개 금액이 B의 기록, 랭킹, 예산 응답에 없는지
- 비공개 인형 사진의 signed URL이 B에게 발급되지 않는지
- 예산 경계 시각의 실제 `timestamptz` 합계

## 4. 데모로 배포하지 않기

Supabase 변수가 없는 배포는 누구나 데모 계정으로 들어오는 공개 연습 모드입니다. 인터넷에 올리지 않습니다.
