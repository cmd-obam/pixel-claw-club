# 배포

## 1. Supabase

1. 프로젝트를 만듭니다. 화면은 이메일 가입을 쓰지 않습니다. 서버가 내부 계정을 만들 수 있도록 Email 공급자는 켜 두고, 공개 회원가입은 꺼도 됩니다.
2. `supabase/migrations` 파일을 번호 순서대로 SQL Editor 또는 Supabase CLI로 적용합니다. 이미 적용한 파일은 다시 실행하지 않습니다.
3. `20261020000003_storage.sql`은 `storage` 스키마가 있는 Supabase에서만 적용합니다. 현재 운영 데이터베이스에는 `20261021000004_pin_auth.sql`을 다시 실행하지 않습니다. 그 파일은 자격 컬럼을 지웁니다. 닉네임 등록 함수는 `20261021000005_club_member_auth.sql`만 한 번 실행합니다.
4. 서버 환경변수에 `SUPABASE_SERVICE_ROLE_KEY`를 넣습니다. 이 값은 브라우저로 보내지 않습니다.
5. `/auth`에서 닉네임과 비밀번호로 가입합니다. 서버가 사용하지 않은 캐릭터를 배정하고, 첫 사람이 방장입니다. 이미 가입한 사람은 닉네임과 비밀번호로 입장합니다.
6. 활성 멤버가 세 명이 되면 추가 등록은 데이터베이스에서 거절됩니다. `20261022000002_remove_verify_a.sql`은 검증A 테스트 계정만 지우는 일회성 파일이며, 다른 회원이 생긴 뒤에는 실행하지 않습니다.

## 2. 앱

Vercel 또는 Node 서버에 배포합니다. 환경 변수는 `docs/configuration.md`와 같습니다. 서버리스 요청 안에서는 작은 이미지의 픽셀 변환만 처리합니다. 원본은 변환 실패 시에도 유지됩니다.

`sharp`는 서버 외부 패키지로 설정되어 있습니다.

## 3. 확인

배포 후 세 계정으로 다음을 직접 확인해야 운영으로 볼 수 있습니다.

- 네 번째 멤버 거절, 닉네임 중복 거절, 틀린 비밀번호 거부
- 멤버 A의 비공개 금액이 B의 기록, 랭킹, 예산 응답에 없는지
- 비공개 인형 사진의 signed URL이 B에게 발급되지 않는지
- 예산 경계 시각의 실제 `timestamptz` 합계

## 4. 데모로 배포하지 않기

Supabase 변수가 없는 배포는 누구나 데모 계정으로 들어오는 공개 연습 모드입니다. 인터넷에 올리지 않습니다.
